
Transaction:-
=============

 the process of combining all related operations into a  single unit and executuing then according to rule "either all operations should succeed or none should succeed"
is called  transaction management.

a transaction is considered a single unit of work and fallows the principle "either all or none";

example: Funds Transfer
consider a money transfer process between two accounts:
Debit amount from the sender's account
credit amount into the receiver's account
both operations should be executed as a single transaction.
if the amount is debited from the sender's account successfully, but crediting
 the recevier's account fails, it may lead to data inconsistency problems.

there are two types of transactions

1.Local transaction
-------------------
in local transactions all operations of a transaction are executed on the same database.

example:

funds transfer from one account to another account where both accounts belong to same bank.

2.Golbal transaction
--------------------

in global transactions all operations of a transaction are executed on the different databases.

example:

funds transfer from one account to another account where both accounts belong to the different banks.


ACID properties:
===============

Atomicity: all or nothing
consistency:  the database remains in valid state.
isolation: transactions do not interface with each other.
Durability: committed changes are permanent.


TCL(Transaction control Language):-
=================================

1.commit
--------

commit is used to permanently save all changes made during the current transaction into the database.

once committed.

changes become permanent
other users can see the changes.
you cannot undo the changes using rollback.

2.rollback
----------

rollback is used to undo all changes made in the current transaction before a commit.

if something goes wrong. rollback restores the database to its previous state.

Introduction to stored procedures:-
==================================

a stored procedure is a named, precompiled collection of one or more sql statements that is stored inside the database and can be executed called wherever required. instead of sending long block of sql from an application every time, the application simply calls thee procedure by name.

why do we use stored procedures?
---------------------------------

1.performance
2.resuability
3.security
4.reduced network traffic.
5.maintaianbility
6.consistency.


advantages:-
==========

faster execution after completion
reduce duplicate sql.
supports transaction, loops, conditions, variables...etc.
easy maintenance..

disadvantages:-
==============

debugging can be difficult.
vendor specific syntax.
complex procedures may become hard to maintain.


syntax to create stored procedures
=================================

DELIMITER //
CREATE PROCEDURE procedure_name()
BEGIN
--- sql statments
END//
DELIMITER;

IN parameter
-----------

an IN parameter is used to pass a value into a stored procedure.
the procedure can use the value, but changes made to the parameter inside the procedure are not returned to the caller.

syntax
------
DELIMITER //
CREATE PROCEDURE procedure_name(IN parameter_name datatype)
BEGIN
     sql statements
END;

DELIMITER;
